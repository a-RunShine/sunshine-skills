# publish-pack.md 模板

> 交付文档。跟 `brief.md`（决策文档）并列。
> 用途：把审稿通过后的发布配套（标题/正文/Tag/钩子/时间/动作）一次性打包，
> 用户照着这个文档就能在小红书完成发布 + 后续动作。

---

## 路径与命名

```
xiaohongshu/<主题>/publish-pack.md
```

跟 `brief.md` 同目录。

## 填写规则

1. **风格基线**只放 hex 值，**详细描述见 brief.md**——避免两份文档互相抄
2. **标题候选 5 条**要有差异化（反转型/走心型/方法型/精准型/数字反差型），不能是同一个意思的 5 种说法
3. **正文 3 备选**必须是真正可独立使用的 3 份（不是同一份的 3 个变体），长度相近
4. **Tag 严格控制 5-10 个**，不列"备用"——备用列表让用户决策瘫痪
5. **发布顺序表格**里"走心感"列必须填 ✅/❌，方便用户发布时检查"封面是否够抓"
6. **发布时间按 3 类人群分**——考研党 / 学生职场 / 自由职业者，不要给"通用 2 个时段"敷衍
7. **发布后动作清单**必须明确 1h/24h/48h 三档，缺一不可
8. **不要重复 brief.md 的内容**——风格基线只列 hex，决策理由看 brief

---

## 颗粒度边界

✅ **要写进 publish-pack**：
- 5 个标题候选（带选择建议）
- 3 个正文备选
- 5-10 个 tag
- 1 条评论区置顶（评论+收藏双钩）
- 发布顺序表格（含走心感）
- 发布时间（按 3 类人群）
- 发布后动作 1h/24h/48h 三档
- 风格基线 5 个 hex 值（一行表格）

❌ **不要写进 publish-pack**（这些属于 brief）：
- 受众/角度/调性/玩梗路线
- Grill 对齐记录
- 关键风险点
- 内容结构（图清单已在 brief）
- 风格规范的详细描述（只列 hex，详细见 brief）
- 决策理由（"为什么这么定"留给 brief）

❌ **不要写进 publish-pack**（这些属于图本身）：
- 8 张图的内容（已经出图了）
- 单张图的文案（写在图上）

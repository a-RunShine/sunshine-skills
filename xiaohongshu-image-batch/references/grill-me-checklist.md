# grill-me 提问清单

按 `/grilling` 原则：**一次问一个问题 + 每次给推荐答案**。
Grill 完的决策落到 `project brief.md`（唯一文档）。

---

## 提问模板

每道题用 `ask_user` 问，结构：
1. 问题（具体、可回答）
2. 候选（2-3 个 + 自定义位）
3. **我的推荐**（放在 description 或追问里）
4. **推荐理由**（简短、给用户判断依据）

**示例**：
> **Q1：你想给谁看？**
> - 刷 LeetCode 备战实习/秋招
> - 大厂在职程序员
> - 编程小白 / 转码人
> - 泛爱好者
> - 自定义：<用户填>
>
> **我的推荐**：刚入门算法题的人/大学生/科班
> **理由**：你已经在刷题，方向是实习，这个画像能让内容"刚够得着"——不堆 jargon、又有干货

## 问题清单（按顺序问）

### Round 1：受众（谁看）

**Q1：你想给谁看？**
- 候选：刷题备战 / 大厂在职 / 编程小白 / 泛爱好者
- 我的推荐：**刚入门算法题的人/大学生/科班**
- 理由：原对话就这个画像；刚入门决定了"卡多深"

### Round 2：角度（怎么切入）

**Q2：内容怎么切入？**
- 候选：全解法对比 / 单一最优解 / 思路+代码 / 面试对线 / 不带代码
- 我的推荐：**全解法对比**（方法 1 + 方法 3，跳过方法 2）
- 理由：方法 2（栈）"简洁但没快很多"是次优，对比意义不大；1 vs 3 的代码量反差天然是内容梗

### Round 3：调性（账号风格）

**Q3：账号调性走哪个？**
- 候选：学霸干货 / 反差玩梗 / 陪伴成长 / 工具极客
- 我的推荐：**反差 / 玩梗 / 自嘲派**
- 理由：方法 1 vs 方法 3 的代码量（30 vs 13）天然适合做"自嘲"梗——"我凌晨 3 点 vs 大佬 5 分钟"

### Round 4：风格基线（图视觉）

**Q4：图的视觉风格定哪个？**
- 候选：暖色手绘 / 莫兰迪粉 / 极客深色 / 学生笔记
- 我的推荐：**暖色手绘（米色 + 淡蓝描边 + 奶油黄高亮）**
- 理由：原素材图 2 已经是这个调性，作为锚图天然省事；暖色调平衡"代码硬核"内容

### Round 5：玩梗路线

**Q5：反差 / 玩梗具体走哪条线？**
- 候选：室友同事反应 / 自嘲把自己挂起来 / 词文思辨型 / 你定
- 我的推荐：**自嘲派**（"我 50 行 vs 大佬 5 行"）
- 理由：直接对应方法 1 vs 方法 3 的代码量差，数字反差本身就是爆款标题公式

### Round 6：出图形式

**Q6：出图形式？**
- 候选：1 主图 + 3-5 轮播 / 1 张信息量超载大图 / 3-5 张轮播不上主图
- 我的推荐：**1 主图 + 5-7 细节**
- 理由：小红书算法号标准做法；保留主图抓眼 + 细节完整

### Round 7：是否要代码块

**Q7：要不要代码块？**
- 候选：要（带代码算法题解）/ 不要（生活/读书/随笔）
- 我的推荐：**要**（带代码）
- 理由：算法题解必须有代码；走 VS Code 默认配色，开发者熟悉感最强

### Round 8：代码块语法高亮

**Q8：代码块高亮配色？**
- 候选：VS Code 默认 / 紫色调 / 简化版无高亮
- 我的推荐：**VS Code 默认**（关键字蓝、类名黄、变量白）
- 理由：标准且开发者最熟悉

### Round 9：封面主题

**Q9：封面主题？**
- 候选：带你刷力扣 / 算法日记 / 30 天刷题 / 自定义
- 我的推荐：**带你刷力扣 #234**（带系列号）
- 理由：系列号建立账号定位；用户期待"下一期"

### Round 10：新增页（如有）

**Q10：要不要在封面后加一张图（官方题目描述）？**
- 候选：要 / 不要
- 我的推荐：**要**
- 理由：让读者一眼看到官方题面、约束、进阶要求（进阶 = O(1) 空间 = 方法 3 的钩子）

```
          ├─ 等用户答

          ├─ 等用户答

          ├─ 等用户答
Q4 风格 ──┤
          ├─ 等用户答
Q5 玩梗 ──┤
          ├─ 等用户答
Q6 形式 ──┤
          ├─ 等用户答
Q7 代码   ┤
          ├─ 等用户答
Q8 高亮   ┤
          ├─ 等用户答
Q9 封面   ┤
          ├─ 等用户答
Q10 新增页┘
```

每答完一题就更新 brief 对应 section。

## Grill 完之后

1. **展示 brief 给用户**："这是我们刚对齐的 brief，对吗？"
2. **用户确认后** → 才进 Step 2 锚图定风格
3. **不要在用户确认前** → 出图 / 选锚图 / 任何执行

⚠️ `/grilling` 红线：**"Do not act on it until I confirm we have reached a shared understanding."**

---

## Grill 提问数量建议

- **最少 4 题**（4 维度：受众/角度/调性/风格）
- **最多 10 题**（加上玩梗/形式/代码/封面/新增页）
- **超过 10 题**用户会烦——能合并就合并
- 关键决策不可省，但具体选项可以简化

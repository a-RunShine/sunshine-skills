# 内容结构（Content Structures）

按"是否带代码"分 3 套结构。决定 6-8 张图的顺序和每张的角色。

---

## 结构 A：带代码（算法题解类）⭐ 经典

**适用**：LeetCode、牛客、剑指 offer 等算法题解。

**图顺序（7 张推荐）**：

1. **封面**（系列号 + 核心梗 + 对比视觉）
2. **官方题目**（描述 + 示例 + 约束 + 进阶）
3. **科普铺垫**（这是什么 + 可视化）
4. **方法 1 笨办法**（自嘲 + 代码 + 复杂度）
5. **方法 N 巧办法**（惊艳 + 代码 + 复杂度 ⭐）
6. **复杂度对比**（表格 + 金句）
7. **万能模板**（三步法 + 收藏钩子）

**替代变体**（6 张精简版）：
- 合并官方题 + 科普铺垫 = 1 张（适合题本身简单）
- 合并复杂度对比 + 万能模板 = 1 张（适合只讲 1-2 个解法）

**替代变体**（8 张详细版）：
- 在方法 1 之前加 1 张"思路一图流"（动画思路 / 流程图）
- 在方法 N 之后加 1 张"踩坑点"（常见错误 / 边界情况）

---

## 结构 B：不带代码（生活 / 读书 / 随笔类）

**适用**：生活方式、读书笔记、随笔、种草、情感。

**图顺序（6-7 张推荐）**：

1. **封面**（核心观点 + 视觉对比）
2. **引入**（背景 / 为什么聊这个）
3. **核心观点 1**（独立卡片）
4. **核心观点 2**（独立卡片）
5. **核心观点 3**（独立卡片）
6. **反转 / 总结**（出乎意料 / 金句）
7. **行动号召 / 收藏钩子**

**变体**：
- 5 张精简版：合并核心观点为 1 张 + 总结
- 8 张扩展版：每个核心观点 2 张（图解 + 金句）

---

## 结构 C：混合（技术 + 场景）

**适用**：技术评测、产品对比、工具教程、debug 案例。

**图顺序（6-8 张推荐）**：

1. **封面**（核心梗 / 痛点）
2. **场景引入**（"你是否遇到过..."）
3. **原理讲解**（带图示 / 流程图）
4. **案例分析**（带代码 / 截图）
5. **进阶 / 优化**（带对比）
6. **总结要点**（5 条核心）
7. **行动号召**

---

## 封面策略

封面的 3 种基础套路（可叠加）：

### 套路 1：数字反差
- "我 50 行 vs 大佬 5 行"
- "3 道题，1 个套路"
- "复习 30 天 vs 7 天"

### 套路 2：自嘲 / 反转
- "室友看到我的解法沉默了"
- "我凌晨 3 点的解法"
- "面试官看完点了点头"

### 套路 3：场景共鸣
- "为什么你的链表总是 TLE？"
- "我刷了 100 道题，发现..."
- "面试被问到这个，答错了"

⚠️ **封面是单独决策点**：
- 风格可以比内容页略夸张（首图要抓人）
- 但**底色和字体感觉必须和内容页统一**
- 单独出图，不在内容批里出

## 节奏感设计

小红书图文"刷到即停"的节奏：

| 位置 | 角色 | 视觉强度 |
|------|------|----------|
| 封面 | 钩子 | 强（夸张对比） |
| 官方题 / 引入 | 留人 | 中（清晰规整） |
| 科普铺垫 | 共鸣 | 中（可爱图示） |
| 方法 1 | 自嘲 | 弱-中（铺垫） |
| 方法 N | 惊艳 | 强（核心干货） |
| 对比 | 升华 | 中（清晰对比） |
| 模板 | 收藏钩子 | 中（清晰可记） |

**原则**：方法 N（巧办法）要做得最饱满，因为这是核心干货。
**原则**：封面抓眼、方法 N 留人、模板收口。

## 系列号策略

**Slogan 形式**（推荐）：
- "带你刷力扣 #XX"
- "XX 算法日记 Day XX"
- "30 天刷题计划 · 第 XX 天"

**主题分隔符**：
- 标签位：`#234`（题号）/ `#XX期`（系列号）

**为什么需要系列号**：
- 强化账号定位
- 让用户期待"下一期"
- 内容可被搜索回看

⚠️ **系列号变了要更新**：每期内容、封面的系列号都要保持一致。
